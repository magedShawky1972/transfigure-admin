# Architecture rules

- Original Orders Breakdown filters operate on loaded original lines using the same catalog resolver as displayed identifiers; all column criteria combine before grouping and totals so visible rows and amounts agree.

- Sync Orders to Odoo and its Sajel sender share the order-body builder in the edge `_shared` directory so previews, audit bodies, and outgoing requests keep the same root header and attribute ordering.

- The six incoming sales/catalog APIs await the shared KOON relay only after successful local saves; expose and audit a separate delivery result without rolling back local data or automatically retrying insert-only payments. Admin users may manually retry only failed KOON log entries through the authenticated retry function, which relays the saved KOON body without repeating the local save. KOON sends read the current admin-managed provider key from the service-role-only settings table on every attempt; the existing gateway connection is only a fallback when no key is saved, and a configured-key failure must never fall back to another key. Admin backfill runs select all orders by inclusive integer order-date range, prepare their related customers/catalog/lines/payments in six separately tracked dependency-ordered phases, skip earlier successful deliveries, and process resumable batches without automatic retries of failed items. Preparation may be restarted only when no delivery has been attempted.

- Custom outgoing email transports must check the shared email-policy before any SMTP/provider connection; email-only handlers reject disabled requests before side effects, while mixed workflows keep their non-email operations running.

- Product API upserts must use each target table's unique identity (production product ID, test SKU), because production SKUs are not unique.
- Customers Without Orders uses a paginated security-invoker RPC matching customer phone against non-deleted Purpletransaction orders with inclusive integer date bounds, to preserve RLS and avoid downloading the transaction history. The RPC only lists customers whose registration date falls inside the selected From–To window (inclusive), so only customers registered in that period are reported.
- Payment Method Report uses a paginated security-invoker daily aggregation of non-deleted transactions using integer dates; its RPC and page enforce the latest Reports/payment-method permission or server-validated admin role, so direct calls cannot bypass report security.
- Individual and bulk timesheet recovery share calculation and approval logic; bulk targets only selected employees' visible eligible rows, runs oldest first, and verifies current values on updates to prevent duplicate credits.
- WFH bulk recovery allocates completed approved sessions through a server-validated, row-locking RPC and a read-only allocation ledger; source usage and target reductions commit together to prevent duplicate or unauthorized credits.
- Vacation attendance uses a shared work-duration classifier in ZK processing, timesheet display, and manual saves; read both leave sources before processing so recalculation cannot reintroduce shift lateness or discard vacation punches.
